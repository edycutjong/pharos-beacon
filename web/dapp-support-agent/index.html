dApp Support Agent

Give it a failed transaction hash. It reads the transaction and its receipt, replays the same call one block earlier, and says in plain words why it failed and what to do. No language model: the cause comes from the chain.

      What's ours

      Beyond the requirement list

      Replay, don't guess

      The failed call is replayed with eth_call at the block before, with the same sender, value, data and gas limit: the state it started from. The revert bytes are decoded (Error, Panic, OpenZeppelin token, ownership and pause errors) and token amounts get their symbol and decimals.

      Honest about limits

      An empty revert is explained only when the numbers prove it (a balance or allowance too small), and the report says the cause is inferred. A failure the replay cannot reproduce is reported as exactly that, not dressed up with a cause.

      Proven on strangers' failures

      Two failed mainnet transactions from wallets and contracts we do not control, found by scanning receipts for status 0: one with a reason string, one that cannot be reproduced. Both are in the table above; re-run them.
