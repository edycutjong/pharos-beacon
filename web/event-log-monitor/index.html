Event/Log Monitor

Watches one contract for one event through the Chain MCP's get_logs, decodes every new occurrence into from, to, amount, tx and block, and keeps a cursor so a restart never prints an event twice.

      What's ours

      Beyond the requirement list

      Crash-safe cursor

      Not just a block cursor: every handled event is saved by txHash:logIndex before the cursor moves, so a crash between printing and saving, or two overlapping polls, still cannot print an event twice. Unit-tested for both cases.

      Any event, readable

      Name an event (Transfer, Deposit…) or give a full signature such as a Uniswap V2 Swap. WETH-style src/dst/wad fields are read as from/to/amount, and amounts get the token's own decimals and symbol from eth_call.

      One watcher, two tasks

      The same poller (src/watch) runs the On-Chain Alert Bot, so the no-duplicate guarantee is shared and tested once. See the Alert Bot ↗
