      What's ours

      Beyond the requirement list

      The plan must be on a page

      askQuestion can answer from general knowledge, so a plan only counts when a page it cites (fetched with getPage) contains the method: eth_getBalance, cast send + --value, totalSupply, eth_getTransactionReceipt. If none does, searchDocumentation is tried and the page found that way is labelled as such.

      Checked a second way

      A balance is also read through Multicall3.getEthBalance (eth_call), a receipt's hash must be in the transaction list of the block it names, and a signed send is checked against both balances: recipient +amount, sender −(amount + gasUsed × effectiveGasPrice).

      Refusal-shaped answers caught

      “can't find”, “don't list”, “isn't supported”: a docs answer in any of these shapes is not covered, whatever it cites. No plan is made and no chain client is opened. Press “how do I bridge to Solana?”.

      Built with Claude as a coding assistant. The design, the failure cases and the extra feature were chosen by me; the commit history shows the iterations.
