Dry-Run Executor

Simulates a transaction on Pharos Atlantic before it is sent: eth_call and estimate_gas predict success or the revert reason, the fee and the balances before and after. When the simulation fails, the send is blocked.

      What's ours

      Beyond the requirement list

      Prediction checked

      After a real send the CLI reads the receipt and the balances back and scores its own prediction: gas predicted vs used, fee predicted vs paid, every balance predicted vs on chain. A plain PHRS send was exact; on contract calls estimate_gas ran high (−24.14% on deposit(), −21.39% on a transfer), so the report calls the fee an upper bound. See the recorded runs.

      Revert reasons decoded

      Revert bytes are decoded into Error(string), Panic and the OpenZeppelin token errors, so “1,000,000,000 USDC” fails as ERC20InsufficientBalance(sender, 0, 10^15), not as an opaque hex string. A node refusal (no funds for the value) is reported separately.

      Blocked by construction

      The one call to the sender sits inside the passing branch of the code, and a test hands in a sender that throws to prove a failed simulation never reaches it. The CLI exits 3 on a block.

      How this was built
      Built with Claude as a coding assistant. The design, the failure cases and the extra feature were chosen by me; the commit history shows the iterations.
