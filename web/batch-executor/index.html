Batch Executor

Takes three or more independent sends and bundles them into one Multicall3 transaction, with each call allowed to fail on its own. It simulates every action first, names the one that would fail and why, and compares the gas with sending them one by one.

Simulation only: one eth_call of Multicall3's aggregate3Value plus estimate_gas for the batch and for each action alone. Nothing is signed. Atlantic is read through its public RPC (the Atlantic Chain MCP runs locally, not here).

      Beyond the requirement list

      Drop what would fail

      --drop-failing reads the simulation first, removes every action that would fail, rebuilds the batch from the rest and simulates it again before anything is signed. Tick “drop the actions that would fail” to watch it re-simulate live.

      Gas, said honestly

      The saving is shown estimate against estimate, never an estimate against a receipt. Counting the one-time approve, the first token batch costs a little more than sending alone; the README's “Gas, honestly” section has the measured numbers.

      No stuck PHRS

      aggregate3Value keeps the PHRS of a call that failed inside Multicall3, so a batch with a failing PHRS action is BLOCKED rather than sent. Multicall3's own README warns against approving it; the page says why the token path needs that, and how far.

      Built with Claude as a coding assistant. The design, the failure cases and the extra feature were chosen by me; the commit history shows the iterations.
