Doc-Search CLI

pharos-docs "<question>" asks the Pharos Developer Docs MCP and prints a concise answer with the doc pages it comes from. When the docs have no answer it says so, invents nothing, and lists the closest pages.

Sequence · pharos-docs "how do I deploy a contract?"idle · press Ask live

    Each lamp lights when the Docs MCP answers. An answer is written by the docs' own askQuestion and takes 5–20 s.

    Output

    No question yet. Ask live runs the CLI's own code on the server against the hosted Docs MCP (keyless) and prints what the terminal would print, exit code included.

      What's ours

      Beyond the requirement list

      A stated no-answer rule

      An answer counts only with a cited page and a reply that does not open by saying the docs lack it. A contrast (“They do say…”) keeps a half-answer, so the faucet question answers what it can and says what is missing. 26 tests pin it against replies seen live.

      Sources a reader follows

      Pages the answer itself links come first; the docs' own source list is de-duplicated, made absolute, and two pages with the same title are told apart by their docs section (“Write Your First Token (foundry)”).

      Made for scripts too

      Exit 0 answered, 3 not found, 2 bad usage, 1 failure; --json prints the structured result; --goal tailors the answer. The Rendered and --json tabs above are the same result the terminal shows.

      How this was built
      Built with Claude as a coding assistant. The design, the failure cases and the extra feature were chosen by me; the commit history shows the iterations.
