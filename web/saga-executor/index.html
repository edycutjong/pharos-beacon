Saga Executor

Four steps that depend on each other: approve, swap, approve, deposit. Each one is checked by reading the chain back before the next starts; a transient failure is retried, a permanent one rolls back what landed, newest first, and a crash-safe journal lets a killed run resume without sending a swap twice. The pool and the vault are our own test contracts, because Atlantic has none.

      What's ours

      Beyond the requirement list

      Crash-safe

      A journal is written before each send, so a killed run resumes from it and checks the chain before it sends again: the swap is never sent twice.

      Verified by reading back

      A step is done when the allowance, the Swap event, the balances or the vault shares read back as expected, not when the receipt arrives.

      Rollback that checks itself

      Undo runs newest first and ends by comparing balances with the start, so a rollback that left something behind says so.

      Built with Claude as a coding assistant. The design, the failure cases and the extra feature were chosen by me; the commit history shows the iterations.
