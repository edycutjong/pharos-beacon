Recurring Payment Agent

Rent, a subscription or payroll on Pharos Atlantic: a plan says weekly or monthly, how much, which token and to whom; a ledger makes sure each period is paid once, and a failed or unaffordable period is never paid twice.

Reads only: it loads the committed plan and ledger, checks every paid transaction on Atlantic, reads the payer's balance and estimates the next payment's gas. It never signs. Atlantic is read through its public RPC (the Atlantic Chain MCP runs locally, not here).

      What's ours

      Beyond the requirement list

      Signed, recorded, then sent

      The signed transaction's hash, nonce and raw bytes go into the ledger before the node sees them. After a crash the next run looks that hash up and, if the node lacks it, re-sends the same bytes: sending twice cannot pay twice.

      One retry, same nonce

      If the node refuses a send, the agent waits and retries once on the same nonce, so at most one transaction can land; a second refusal marks the period failed. Covered by unit tests; the live runs did not hit a refusal.

      A Discord receipt per payment

      With --discord every confirmed payment posts one receipt; its message id is stored in the ledger, so a re-run sends no second one. The ids are in the ledger the live run loads (Raw JSON).

      How this was built
      Built with Claude as a coding assistant. The design, the failure cases and the extra feature were chosen by me; the commit history shows the iterations.
